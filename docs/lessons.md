## 6. Lessons learned
- androidx.mediarouter's `MediaRouteChooserDialog` extends `androidx.appcompat.app.AppCompatDialog`, and mediarouter does not expose appcompat at compile time. Using mediarouter dialog classes requires `implementation(libs.androidx.appcompat)` in app/build.gradle.kts (catalog alias `androidx-appcompat`).
- You cannot read the Gradle cache (~/.gradle/caches): OpenCode denies external directories and the run aborts. Do not try. Verify an API by compiling (gradlew.bat assembleDebug) instead.
- `android.media.AudioDeviceCallback` is a top-level class (not nested in AudioManager). `AudioManager.AudioRecordingCallback` IS nested.
- Only the repo directory is readable/writable for you. Never write or read files in %TEMP% or other outside paths; pipe Gradle output to the console or to build/.
- Scaffold applies insets only to its content padding. Custom composables in bottomBar/topBar must handle navigation/status bar insets themselves (navigationBarsPadding()).
- `awaitEachGesture` cannot call `Animatable` suspend functions. Launch them on `rememberCoroutineScope`.
- Room 2.8: `implementation(libs.androidx.room.runtime)` and `ksp(libs.androidx.room.compiler)`. Do not add `room-ktx`. KSP plugin: `com.google.devtools.ksp` version `2.3.12`.
- `NavHost` destination `route` is the pattern string (`playlist/{playlistId}`), not the filled path.
- A decorative stroke on `#0E0E12` needs about 40% white to reach ~3:1. White at 14% disappears.
- Noto Sans Tamil has no U+2026. `TextOverflow.Ellipsis` on that family draws the mark twice. Keep the original characters and paint Tamil as a Noto span inside a Jakarta paragraph so one Jakarta ellipsis is drawn. Do not slice the string.
- Carousel v2: icons ride the ring on faint glass beads; a fixed opaque glass lens (pill) sits at the front and each icon crossfades/grows into the lens tint as it passes (`frontness`). Per-frame values are read only in `Layout` placement (`placeWithLayer`), layer and draw lambdas; `selectedIndex` is `derivedStateOf`. Motion is M3 Expressive: ring `spring(0.8, 380)` carrying the release velocity to `flingTarget` (0.22 s projection, max one turn, one spring, no decay-then-snap), lens press `spring(1.0, 3800)`, lens settle `spring(0.6, 800)`. `SegmentFrequentTick` per detent while the user drives it, `SegmentTick` on settle. Animator scale 0 = reduce motion: snap, no momentum, no blur. Labels hand off (`labelAlpha` is 0 at the half step). The older tile notes below describe v1 geometry, which is unchanged (radius, scale, alpha, tilt, lift).
- The bottom nav is a 3D carousel of glass tiles (`CarouselMath` + `NavCarousel`), not a stroked arc. Eight sections, 45° apart, radius `0.44 * width`. Tiles are 44–60dp, independent of the ring so a wider orbit does not grow them. At rest the front, ±45°, and ±90° are visible and symmetric; the back is hidden (`cos θ < -0.1`). Scale, alpha, `rotationY`, and the upward Y offset all come from `cos θ`. Apply scale and `rotationY` on one `graphicsLayer` (`cameraDistance` `12 * density`). Shade the plate only. One 13sp semibold label sits under the front tile. `graphicsLayer.density` is a Float; capture `LocalDensity.current.density` before the layer lambda.
- The mini player and carousel live in `SectionScaffold`'s `ChromeSlot` (opaque `pageFill`), under a `ListViewport` that fades its last 32dp (`ListEdgeFade`) into that fill. Do not overlay chrome on the list. Keep `MiniPlayerCarouselGap` at 8dp so the unchanged mini player sits snug above the compact ring. Hide the bar on the full Now Playing route. In two-pane with a loaded track, the same chrome slot is window-wide under the split. Without a mini player, keep the carousel in the list column's chrome slot.
- `OutputRoute.classify` is pure. Car is `TYPE_BUS`, car mode, or Bluetooth major `AUDIO_VIDEO` with hands-free / car-audio. A denied `BLUETOOTH_CONNECT` (API 31+) or a `SecurityException` from `bondedDevices` is `RouteIcon.UNKNOWN`, drawn as the generic Bluetooth glyph. `AudioDeviceCallback` is the top-level `android.media.AudioDeviceCallback`.
- `likedAt` and `playCount` live on the existing `favorites` row. Add them with `ALTER TABLE` (`MIGRATION_3_4`); do not drop the table. Unliking clears `likedAt` and keeps `playCount`. Do not build the like-weighted shuffle.

## Stack lessons V2-V17 (moved from the feature-branch AGENTS.md on 2026-10-18)
- [V2 video library] Nothing failed, but two choices were easy to get wrong: a `ViewModel` whose primary constructor takes test seams (repository, IO dispatcher) is no longer creatable by the default `viewModel()` factory, and registering a Coil fetcher on a new app-wide `ImageLoader` would have changed how music artwork loads -> keep an explicit `constructor(application: Application)` next to an `internal` seam constructor, and attach custom fetchers per request (`ImageRequest.Builder.fetcherFactory`) on a distinct model type (`VideoThumbnail`). For Robolectric ViewModel tests pass `Dispatchers.Unconfined` as the IO dispatcher so `refresh()` completes inline on the paused main looper, and fake MediaStore with `Robolectric.buildContentProvider(...).create(MediaStore.AUTHORITY)`.
- [V3 videos section] Coil's `AsyncImagePreviewHandler { request -> image }` factory must return a non-null `Image`, so the first build failed when odd rows returned null to show the fallback; and Pillow's `getbbox()` on RGBA diffs only checks alpha, so the first screenshot diff reported 50 changed PNGs with no box -> implement the fun interface `AsyncImagePreviewHandler { loader, request -> State }` and return `AsyncImagePainter.State.Error(null, ErrorResult(null, request, e))` per request; diff screenshots after `convert('RGB')` and check each changed PNG's diff box sits in the carousel band. A 9th `NavSection` re-baselines every compact and expanded carousel shot (50 here) while non-carousel shots stay identical. Read a permission-gated ViewModel's `uiState.value` (not the collected Compose state, which can lag a frame on its initial Denied) before launching a first-visit request.
- [V4 inline player] Nothing failed except one compile: libVLC 3.7 moved the track types to `org.videolan.libvlc.interfaces.IMedia` (`IMedia.VideoTrack.Orientation`), so `Media.VideoTrack` is unresolved; `getCurrentVideoTrack()`, `Media(ILibVLC, FileDescriptor)`, `setHWDecoderEnabled`, `attachViews(layout, null, true, true)` and `setTime(long)` compile with zero `w:` -> for libVLC 3.7 import track types from `interfaces.IMedia`. Two design traps: libVLC's Android vout needs a surface before the first frame, so `VlcVideoEngine` defers `play()` until a view is attached; and `MediaPlayer.pause()` is only called while `isPlaying`, so it can never act as a resume if the native call toggles. A Compose `AndroidView` (a custom test `View.onDraw`) does render in Roborazzi NATIVE mode, so the fake engine's placeholder frame shows in screenshots; put a transparent clickable box over the `AndroidView` so the view never eats the tap.
- [V5 two-pane video] Nothing failed (first targeted run and the clean build were green, 0 `w:`), but three traps were avoided: (1) two-pane had separate mini/no-mini branches, so hiding the mini player for a video re-hosted the NavHost and dropped the left pane's saveable state; (2) Back must close the video before NavHost pops; (3) the activity builds `VideoViewModel` with the default factory, so a real-activity test cannot inject an engine -> keep one two-pane tree with only the chrome slots conditional (screenshots stayed byte-identical), compose `BackHandler` after the NavHost so its callback is newer and wins, and swap libVLC in `MainActivity` tests through `VideoViewModel.testEngineFactory` reset in a rule's `finally`. A fold is a new composition, so a "left the Videos route" rule must compare against a remembered previous route that starts null, or the fold itself pauses the video.

- [V6 fullscreen] Two test traps, both fixed before commit: (1) the first unfold-without-recreate test went Compact `xxhdpi` -> Expanded `xhdpi`, and the density change is not in `configChanges`, so Robolectric recreated the activity; (2) a DataStore pref written in one Robolectric test leaked into the next (the `preferencesDataStore` delegate is one instance per JVM) and its async write posts to the paused main looper, so `waitUntil` never saw it -> keep the density fixed when a test means "unfold without recreate" (`Robolectric.buildActivity(...).setup()` + `RuntimeEnvironment.setQualifiers` + `controller.configurationChange()` + `createEmptyComposeRule()`), and when a real-activity test flips a DataStore pref, set it explicitly at the start, idle `shadowOf(Looper.getMainLooper())` inside the wait, and restore it in `finally`. Fullscreen is drawn over the whole window by `MusicApp` (the NavHost entry is an empty placeholder), so the NavHost is never re-hosted; the layout beneath is `clearAndSetSemantics`, and only one `VideoSurface` is composed at a time (the pane's is dropped while fullscreen).
- [V7 tracks + error log] Four traps: (1) a KDoc containing `` `audio/*` `` or `` `*/*` `` opens a nested `/*` comment in Kotlin and the whole file fails with "Unclosed comment" plus dozens of cascading unresolved references -> never write `/*` inside a comment; (2) `androidx.core.util.AtomicFile`'s rename-over-existing fails on Windows, where Robolectric runs here, so the second write silently never landed -> write a temp file and `Files.move(REPLACE_EXISTING, ATOMIC_MOVE)`; (3) on `viewModelScope` (Main.immediate) with an Unconfined IO seam a launched job can finish before `trackJob = launch {}` is assigned, so "is this still the current job" checks must use a token set before `launch`, and anything a cancelled `withContext` returns (a `ParcelFileDescriptor`) must be claimed inside the block or it leaks; (4) a truncated jar in the shared `~/.gradle` cache ("zip END header not found", another Gradle mid-download) fails `testDebugUnitTest` at class scanning -> wait and retry, never touch the shared cache. Also: `createComposeRule` (v1) is deprecated and is a `w:` -> use `androidx.compose.ui.test.junit4.v2.createComposeRule`; LazyColumn keys built from content crash on two equal entries (error logs repeat) -> no key for append-only logs; redaction regexes need folders with spaces, SAF doc ids (`primary:…/`), `file:/` and `*_token=` cases. libVLC 3 cannot open `content://` slaves: subtitles are copied to cache with their extension (`file://`), audio goes `fd://N`, unverified on device.

## Lesson (V14): one fast-changing value at the top of the tree drags every frame
- libVLC TimeChanged fires many times a second. Each tick made a new VideoUiState, and MusicApp collects videoState at the root, so the whole app recomposed per tick. TextureView is composited on the app UI thread, so a busy main thread dropped video frames inline, fullscreen and in PiP (5-10 fps).
- Publish the UI clock at about 4 Hz (domain/PositionThrottle, 250 ms) and publish immediately when any other field changes.
- Anything that saves or reports a position (resume checkpoint, media session) must read the engine's exact position, never the throttled UI copy. Do not bend a test tick to fit a throttled value.
- One "Playback check" info entry per play (Media.Stats displayed/lost over 5 s plus HW/SW decoding) tells us on-device fps without a profiler.

## Lesson (V14, A/V sync review): measure the pipeline before guessing
- Second opinion (GLM 5.3 Flash, max) agreed TextureView + UI-thread work is the frame-pacing risk and found two more things: the animated app background kept redrawing every frame behind the video (now static while a video is open), and setHWDecoderEnabled(false, false) only adds ":codec=all", so "hardware decoding off" still used MediaCodec. Off now adds ":codec=avcodec,all".
- libVLC 3.7.7 picks --aout=android_audiotrack on modern phones (opensles only on a few old SoCs), has no aaudio module, and appends "--android-display-chroma RV16" when none is given. It has no decoder-name getter and no log callback, so the log names the decoder we asked for.
- With audio as the master clock, a slow video path drops pictures (lostPictures); it does not delay audio. Audio "behind" the picture points at audio latency (often Bluetooth) or at late TextureView latching. The playback check now logs frames decoded/shown/lost, audio buffers played/lost and the audio route, so one log line tells which.

## Lesson (V15): one picture, many hosts, motion from where the user looked
- The engine owns the video and subtitle SurfaceTextures and gives them to libVLC once per MediaPlayer. Hosts (box, pane, fullscreen) only show those textures through VideoTextureFrame, so moving between hosts never touches the decoder and cannot blink. Aspect and fit are a TextureView transform (VideoFit), not a relayout.
- Hosts form a stack. When the top host leaves (fullscreen closes), the picture goes back to the newest remaining host. Without the stack, closing fullscreen left the box black.
- Fullscreen grows out of the box: the box reports its window bounds (LocalVideoBounds), and a layout modifier lerps from those bounds to the full window with one spring (dampingRatio 1, stiffness 380, about 300 ms). Read progress and bounds only in layout or graphicsLayer lambdas, never in composition. Reduce motion snaps every animation.
- The same box bounds feed the PiP sourceRectHint (null while fullscreen), with seamless resize on, so PiP opens from the box.
- The right pane follows the tab in both layouts: leaving Videos pauses the video (pause also saves the resume position) and the pane crossfades back to Now Playing. Tests that encoded "browsing keeps the video playing" were changed on purpose.

## Lesson (V16): Recently Played records from playback, not from the list that started it
- Recently Played was empty because only playQueue (a tap in a song list) wrote recent_plays. Next, auto-advance, the notification and every video were never recorded. Now PlaylistViewModel.trackHistory watches the song and video states and records an item once it has played 5 s or reached its end (PlayHistoryTracker), into Room table play_history (v6; MIGRATION_5_6 copies old recent_plays as songs).
- A consecutive replay of the same item updates the time instead of adding a row; history is trimmed to 500.
- Day labels (Today, Yesterday, weekday, "Oct 3", plus the year when it differs) are computed from calendar days in the device zone, not 24-hour windows; unit tests pin the zone and cover midnight.
- Once recording works, UI tests that expect an empty Recent screen after something played are wrong. Mark the screen by its title instead.
- When a free model starts adding println debugging to production code instead of reading the failing assertion, stop it and diagnose by hand.

## Lesson (fix-debug-signing): CI debug APKs must share one signing key
- Without a signingConfig, AGP signs debug builds with ~/.android/debug.keystore. Every GitHub Actions runner is fresh, so each run made a new key: two CI APKs had different cert SHA-256s, and Android refused the update with "App not installed" (after Play Protect passed). versionCode was also fixed at 1.
- app/debug.keystore is committed on purpose. It is a DEBUG-ONLY, NON-SECRET key (standard debug credentials: android / androiddebugkey). It is not for release or the Play Store; never point a release signingConfig at it.
- versionCode = GITHUB_RUN_NUMBER in CI (1 locally), so each newer CI APK is an upgrade.
- After this change, uninstall the app once on every phone (old installs carry a different key); after that, CI APKs update in place.
- Check with: apksigner verify --print-certs <apk> on two runs; the SHA-256 must match.

## Lesson (V17): libVLC 3.7.7 attachViews throws with two raw Surfaces
- Every video tap on the Fold crashed with IllegalArgumentException("invalid state") from AWindow.onSurfaceCreated, thrown while attachViews attached the subtitles helper.
- A raw Surface counts as ready (isReady() is true without a SurfaceView), so the video helper already moves the vout to READY and fires onSurfacesCreated; the subtitles helper is the last step of attachViews, and its second onSurfaceCreated throws because the state is no longer ATTACHED. The vout is fully attached at that point.
- The fix is VoutAttach.attachRawSurfaces: it sets both surfaces, catches exactly that IllegalArgumentException when the vout is already attached, and rethrows anything else. VoutAttachTest drives the real AWindow to pin the behaviour.
- Robolectric cannot run libVLC playback, so any change to how surfaces reach libVLC still needs a device check; a crash safety net now records uncaught errors in the error log.
- [V18 c03 first-frame timing] VideoViewModel only sees engine StateFlow, so an event that leaves state unchanged never arrives -> give such signals their own flow on VideoEngine (firstFrames) instead of routing through the reducer.

## Lesson (V18): the first video of a process waited ~9 s for libVLC's fontconfig
- Evidence: libVLC logged "Fontconfig error: Cannot load default config file", then a 9.2 s silent gap before the video output opened; a second video in the same process started in 45 ms; /system/fonts holds 275 files (134 MB).
- Cause: the fontconfig compiled into libvlc.so has the build machine's config path, so on the phone it has no config and no cachedir and rescans every font in each new process, never saving the result.
- Fix: FONTCONFIG_FILE and FONTCONFIG_PATH are set before libVLC starts, pointing at a generated fonts.conf (/system/fonts etc. plus a persistent cachedir) in noBackupFilesDir; on the first run after install a background warm-up plays a 2 KB clip with a subtitle so the cache exists before the first tap.
- Measured by the "first frame N ms" part of the Playback check line.
